# Batch 16 — teacher class ownership gate (PF-01)

Requirement PF-01 remains **Nov 30 delivery**, priority High, source **Not verified**, demo **Visto / Seen**. Original criterion remains: “Teachers see only their classes and mark attendance; what they mark shows at the front desk.” This batch fixes the existing ownership boundary. It does not implement or accept the future teacher-attendance portion: launch attendance remains read-only for teachers, with check-in at reception (0051).

## Scope and behavior

`/#/teach/class/:id` now resolves the effective actor's tenant-scoped linked teacher and owned class before mounting the roster/reviews/notes child. A teacher cannot recover identity from another teacher stored in `hoyos.teach.as`; unlinked/ambiguous teacher accounts fail closed. Home hides the reviewer picker for teachers. Admin/coordinator/super-admin class previews remain allowed under the existing route contract. Finance retains its existing selection on the authorized payroll route; Finance does not gain the class-detail route. No route-role list, permission matrix, backend access policy or grant changed.

The access state is keyed by actor, effective role and class ID. Changing actor/ID removes the previous child synchronously on the next render; superseded async reads cannot restore old content. Teacher/session change events revoke and reread access. Ownership/read failures expose no roster, review, note or member details. Loading and read-error/Retry states are contained. Only an allowed child requests the roster and details. People queries use the class's active participant IDs rather than loading all users/profiles.

Detail results are defensively filtered by tenant and intended session/entity/ID; user/profile rows must match requested participant IDs. A provider that ignores query scope cannot insert foreign rows into the rendered class. Ownership is checked again after detail reads, so reassignment during a request cannot release stale data. Review count/average/tag aggregation and anonymous display remain unchanged; class-note visibility is preserved.

Existing note and class-completion actions reread current ownership inside a mock-only staged command. Reassignment/missing linkage/cross-tenant access rejects before writes. Storage failure rolls back the note or completion+audit; retry can save. An immediate UI in-flight ref prevents double-click duplication. Repeated completion rejects once the class is already completed, without another audit row. No booking attendance state is written. This is a frontend MockProvider consistency improvement, **not authenticated server authorization**; durable backend commands and request-id idempotency remain Anu work.
