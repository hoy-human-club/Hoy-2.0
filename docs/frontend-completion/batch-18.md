# Batch 18 — selected-class return and fictional registration (SW-03 / CU-01)

Requirements retain original **MVP Oct 30**, source **Not verified**. SW-03 High criterion: “Leads to sign-up or sign-in and then to the chosen class.” CU-01 Urgent criterion: “Booking requires an account with name, WhatsApp and email; there is no guest booking.” This batch addresses a browser mock flow; source implementation is not accepted, and real account/authentication criteria remain unverified.

## Scope

A-02 `/#/auth/sign-in` and A-03 `/#/auth/sign-up` preserve a validated `next` through both account-switch links and the duplicate-account sign-in offer. Success returns a customer to the chosen class and mat, full-class waitlist, plan or gift route already emitted by the website. Only these existing destinations/parameters are accepted; external, protocol-relative, privileged, auth-loop, encoded-escape and unexpected-query destinations fall back to `/app`. Existing noncustomer demo sign-in still uses each role's existing home. Route roles/permissions and real auth settings are unchanged.

A-03 visibly requests fictional details only: this creates a browser-local demo customer, does not verify email/WhatsApp, does not store the demo password, may reset with the demo and does not carry to other devices. Clerk remains disconnected. The helper refuses non-mock or non-atomic providers. It preserves current first/last/email/WhatsApp, password validation in the form, emergency contact, optional birthday/photo, marketing/invite data, locale `es`, customer-only role and exact `leg_terms_es` / `leg_privacy_es` consent IDs. It does not choose a legal version or replace required fields with email-code authentication.

Account, profile, customer role, two consents and local request receipt stage together. Current duplicate email/phone is reread within the serialized mock transaction. Storage/write failures leave no partial account; retry uses the same nonce. Unchanged concurrent replay returns one user ID; changed-intent replay conflicts. The receipt contains a SHA-256 intent digest and user ID, without raw contact/photo details or password. The password is omitted from command input and digest. Immediate in-flight guard prevents repeated form submission; cancel/unmount suppress late session/navigation and cancellation checkpoints roll back an in-progress staged command. If the browser commit already completed before leaving, the complete local customer may remain, while late resolution still cannot sign in or navigate; the UI does not claim that Cancel deletes a committed account. Registration alone never books or pays.
