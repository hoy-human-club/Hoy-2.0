# Batch 10 — local problem-report drafts

Stable requirement OT-03, original phase **Nov 30 delivery**, Low, all roles. Exact source criterion: “Sends the report with the screen and the user.” **The sends criterion remains unmet.** This batch implements only the disconnected local-draft frontend identified by the manifest; it is not owner/backend acceptance.

`/#/hub` replaces the report placeholder with an accessible form, validation, preview and explicit browser-local save. It captures the current hash-router pathname, demo user ID/name and effective role. Query strings/full origin are omitted. The preview warns that no report is sent, local drafts do not appear on other devices, and fictional details only should be used. There is no external intake, sharing link, messaging tool or dispatch. Tenant/user/role scope separates local drafts, including a super-admin's different role previews.

No draft is written until the explicit local-save button is pressed. Closing/cancelling leaves the prior saved copy intact. Identical save retries retain the same draft ID/timestamp and do not rewrite storage; storage failure preserves the text and prior saved copy, with a retry control. Loading malformed or unavailable storage reports a failure rather than claiming a draft loaded. There is no database table, submission record, backend credential or access-policy change: this is component-local UI draft persistence.
