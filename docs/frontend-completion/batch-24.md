The frozen preview is not a complete legal export or an authenticated production export. The UI displays counts, allows discard before offering a file, and says only that a download was offered; it cannot know whether the browser/user saved it. A failed preparation or precommit read prevents the offer and prepared audit. A failed ownership/read fence after commit prevents acknowledgement and the file offer but does not undo the committed metadata audit. Audit/receipt contains only counts/IDs/digest, never the exported body.

Deletion requests and cancellations use the existing MockProvider atomic transaction. Required owned account/profile rows and scoped requests are freshly read inside the stage. A new request is rejected if any own requested/processing request exists. Cancellation freshly requires the targeted own request still be requested; processing rejects a stale cancel. Row+audit failure/quota rolls back together. Fresh required account/profile shape and ownership are checked before replay, inside new transactions and after outcomes. Request/cancel replay also requires its recorded target to remain owned; its historical outcome does not impose a new transition on current status. Final preview consumption reads required owned rows again. Scoped nonce and intent digest deduplicate replay; raw reason appears only in its request row and is not duplicated in audit/receipt. No account/profile/payment/invoice/package/booking data is deleted, anonymised or changed by these commands. No message or real provider call occurs. Existing customer/teacher roles and the existing super-admin own-user route bypass are preserved; other roles remain denied.

Page-local synchronous guards share immediate identical work, preserve a failed command's nonce for retry and discard stale/cancelled/unmounted/wrong-context preparation. Account read failures clear stale rows and block actions until Retry succeeds. Cancel copy states that an already committed result cannot be undone. Existing fifteen-business-day wording is preserved verbatim, with no legal interpretation or proof of actual handling. No new schema, role grant, permission/security/provider configuration or real storage service.
