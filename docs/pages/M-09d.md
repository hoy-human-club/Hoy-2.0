# M-09d — Apps and subscriptions

Route: `/#/admin/finance/subscriptions`; local browser storage, not a production backend.

## Delivered
Workspace-scoped AppDependency → Subscription → ActualCharge contracts live in
`src/shared/subscriptions/model.ts`. The identical model and React panel are portable
between HOY and PetRock; host wrappers supply identity, permissions, translations and catalog candidates.
App details include provider/product, purpose/category, HTTPS official/manage links, related projects,
connection state and dated evidence. Subscriptions include nullable expected amount, currency,
monthly/every-14-day/yearly interval, original billing day, next charge, payment display label,
status, owner and evidence. Charges require a distinct reference and evidence and never arise from forecasts.

## Boundaries
- Storage key: `hub.app-subscriptions.v1:<workspaceId>`; workspace IDs `ten_hoy` and `petrock`.
- Records start empty. Catalog entries are possible integrations, not active services or paid bills.
- No server persistence, automatic backup, synchronization, bank/email access, OAuth, credential entry or imports.
- Existing HOY MockProvider, PetRock MockProvider/CompanyOS seam and Stripe stub are unchanged.
- UI permissions: HOY super_admin/admin/finance; PetRock owner/super_admin. Demo sessions are switchable:
  these are UI guards, not production security or server-side tenant authorization.
- Storage failures are visible; corrupt saved records are not overwritten. Stale tabs cannot overwrite newer saves.
- Unknown amounts remain null, zero remains zero, currencies are summed separately. Monthly estimates
  include active subscriptions only; actual totals are independent all-time recorded charges.
- Month ends clamp without losing the original billing day; February 29 annual renewals recover in leap years.
- Actual charge amounts and transaction references remain immutable in the editor. Receipt links, evidence and currency verification can be updated; corrections/refunds and file uploads are not implemented.
- Evidence is a plain reference; verification is a manual assertion. Do not paste sensitive documents.
- Secret-pattern/card-number rejection is a guard against accidental entry, not a secret vault.
- No Playset usage events are treated as vendor subscriptions. No SantaMaria files or services changed.

## Reuse and production follow-up
Copy the shared directory module and provide workspace identity, restricted-role booleans and i18n strings.
Production integration requires authenticated server storage, tenant-scoped foreign keys,
unique `(workspaceId, subscriptionId, reference)` charge constraints, audit history, backups and
conflict handling in a transaction. Existing mocked tables are not advertised as live billing records.

## Public catalog and account/receipt enrichment — 2026-10-17
Five public provider entries (Clerk, Supabase, Resend, Railway, Google Workspace) now show locally bundled recognizable brand marks, dated public USD prices and official source links. Selected paid tiers are a reference snapshot, not an exhaustive plan comparison or a live pricing feed. Catalog values never populate a subscription amount, selected plan, owner or actual charge.

Public pricing: Clerk Pro $25 monthly / $20 per month annually; Supabase Pro from $25 monthly plus compute/usage; Resend Transactional Pro $20 monthly for 50,000 emails, $0.90 per 1,000 overage; Railway Pro $20 monthly minimum including $20 usage and unlimited seats; Google Workspace Business Starter $8.40 per user monthly flexible / $7 annual commitment. Regional prices, tax, promotions and usage vary. Sources: https://clerk.com/pricing, https://supabase.com/pricing, https://resend.com/pricing, https://railway.com/pricing, https://workspace.google.com/pricing.html. The USD Google reference was supplied by native official-source research; the page can localize to other currencies.

Account metadata: account owner, sign-in email, organization label and password-manager/vault/item display reference. No password values, secret-manager deep links, share tokens or new credentials. Subscription metadata: selected plan, billing contact email, receipt inbox email, mailbox type and clean billing portal URL. These are manually entered and do not prove mailbox ownership or connectivity.

Receipt retrieval is manual: open the provider portal, copy the suggested search query, or open a Gmail search in the user's signed-in mailbox. The app does not read email or reconcile receipts. Existing charges can link a clean HTTPS receipt document or Gmail message permalink. Signed URLs and query-token links are rejected. A charge currency may remain unknown; it can be supplied when verifying the receipt. Currency verification is explicit for new charges; unverified currencies are excluded from actual totals. Prior version records remain readable without migration and retain their original explicit currency behavior.

Manual JSON export and same-workspace restore provide a portable backup; restore asks before replacing records and refuses other workspace IDs or secret-named fields. Backups include private account metadata and must be stored privately. Browser storage remains the runtime persistence layer.

Persistence inspection: HOY uses MockProvider and has a SupabaseProvider whose data methods throw not-ready; PetRock uses MockProvider and has a CompanyOS REST adapter that is not selected at runtime. Neither provides an authenticated production store for these records. No secrets, grants, connectors, provider selection or backend configuration were changed.

Brand provenance: `public/brand/services/provenance.json`. Supabase uses its official unmodified SVG; other marks are the current Simple Icons 16.35.0 distribution with official-source references and CC0/trademark notices. Google Workspace uses the recognizable Google provider mark, explicitly recorded as such rather than a fabricated Workspace icon. Brand use is identification, not endorsement or verified account ownership.
