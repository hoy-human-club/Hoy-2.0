# M-14 · Class Schedule / Horario de clases

Route: `/#/admin/class-schedule`. Admin and super-admin only. Calendar, list and table share teacher, modality, room, status and class-name filters. A dated-session drawer edits only that occurrence. Links open the related Content records and weekly template.

## Safety and data status

This is browser-local demo data. The production booking backend and payments are not connected. UI role guards and demo command validation are not a production security boundary. Deploy authenticated tenant-scoped RPCs, database row locks, private compensation RLS and server audits before production writes.

Past, cancelled and completed sessions are read-only. Capacity cannot drop below occupied seats or exceed the room limit. A booked session cannot move rooms. Full snapshots prevent overwriting a concurrent edit.

## Recurrence and editorial defaults

Content holds weekly templates, weekday/time, optional start/end dates and a 50-minute default for new classes. Existing durations are preserved. New templates use explicit preview and generation within a six-week horizon; repeated generation skips existing occurrences, and room/teacher overlaps abort the entire batch. Older demo templates retain their existing on-load expansion. Preview dates use the browser timezone, visibly disclosed; a production generator must use the studio timezone.

Template theme/description are defaults. Each dated class can inherit them (null override), replace them or intentionally hide them (empty bilingual override). Reset restores inheritance. Public schedule booking previews and customer class/checkout screens show the resolved copy. Editorial edits do not change booking, capacity, payroll or layout records.

## Content bulk editing

Select search results or individual records in table/list. Choose one supported field, review named before/after values and apply atomically. Undo is available for the last batch until leaving the entity; it refuses if any affected record changed afterward. Invalid references, unsafe capacity and stale previews change nothing. Publish state is an explicit selected field and is never changed by another batch field. Teacher compensation fields are hidden from roles without payroll write access.

## AD02 · fictional studio cancellation

The admin/super drawer offers a separate review/confirm command for one future scheduled occurrence. The browser prototype must resolve every active sign-up to exactly one consumed unit from an owned original grant. Missing, ambiguous, shared or voucher lineage makes the whole operation unverifiable; this is a prototype limitation, not a new cancellation policy. Successful mock transactions cancel the occurrence/bookings and append exact linked returns atomically with a safe hashed receipt. Original purchases, expiry, freeze and payments remain unchanged.

Stop waiting or closing the drawer aborts an uncommitted command. It cannot undo an already committed cancellation. The same command can verify a committed result after the class starts; required owned rows and result digests are read again. Email templates are shown as previews only: no message, outbox, sent or delivered state is created. Contact/preference/template warnings do not settle recipient policy. Customer readback uses only their own rows to verify an original-term return, otherwise shows unverified; cancelled-class waitlist offers/claims are unavailable. Legacy customer cancellation keeps its existing deadline behavior and rejects the privileged studio reason before writes.
