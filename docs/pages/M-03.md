# M-03 — Tables & relations

**Route** `/#/admin/tables` · `/#/admin/tables/:table` · **Roles** super_admin, finance, developer · **Surface** admin · **Spec** `M03` in `src/modules/admin/specs.ts` (`spec.code === 'M-03'`, see `/#/dev/specs`)

## Purpose
The studio's data manager with views. Any of the 57 tables opens as a grid, list, gallery, board, calendar, timeline or relationship graph, with filters, multi-sort, grouping, hidden columns and views saved for the team (renamed or deleted by their creator). Everything is written in words (Inter headings, DM Sans body; the `snake_case` names appear only in dev mode), a foreign key shows the title of the row it points at and opens it, and the row panel lists what uses the row. Redesigned in 0044 after "it looks like it's only for developers", and calendar and timeline wired in 0046 after "the other views aren't wired"; the schema stays the single source (D-0020) and saved views are rows in `table_views` (D-0021).

## Sections (layout order — `useLayout(spec)`)
1. **`TablesSidebar`** (`tables/TablesSidebar.tsx`) — three states: expanded (desktop), rail (icons and counts) and a sheet on phones. Search, *Fijadas* (pinned), *Recientes* (last 5), the groups as accordions with counts, a provider footer, and "reset demo data" behind a design-system dialog. Collapse with the header toggle or `tables.toggleSidebar`; 44 px targets, arrow keys move, Escape closes the sheet. State in `localStorage['hoyos.tables.prefs']`.
2. **Header** — table icon, human title, kind and group badges, description, row and column counts, and (dev mode) the technical-names toggle.
3. **View switcher** (`SegmentedControl`, `compact`) — Grid · List · Gallery · Board · Calendar · Timeline · Graph all work; Calendar and Timeline are disabled with a hint on tables without a date or timestamp column. Beside it the saved-views menu: apply, save, and (0046) rename or delete a view — its creator or a role with `tables.write`; delete asks in a design-system dialog.
4. **Toolbar** (`tables/Panels.tsx`) — in the calendar and timeline views a **Fecha / Hasta** picker (`DateColumnPicker`) chooses the start column and the end column (date and timestamptz columns plus `created_at` / `updated_at`; `time` columns are excluded because they cannot place a row on a day; "no end" draws a point). Filter builder (operators by column type: is, is not, contains, empty, not empty, before, after, greater, less, in), multi-sort, group by, columns (show, hide, reorder), search, JSON / CSV export, the schema toggle, new row. Active filters show as removable chips. "Save view" writes the whole state into `table_views`.
5. **Views** (`tables/Views.tsx`, `tables/GraphView.tsx`, `tables/SchemaView.tsx`)
   - **Grid** — `DataTable` with `hiddenColumns`, `groupBy`, `multiSort`, `onCellRender`; FK cells show the referenced row's title (id in the tooltip) and open it.
   - **List** — one `ListRow` per record, title first, the other visible fields inline.
   - **Gallery** — `Card` grid from `titleColumn` and the first media or text columns.
   - **Board** — `KanbanBoard` (new organism): one lane per value of an enum or boolean column (default `status`); drag with the pointer or the keyboard (dnd-kit), or use the "Move to…" select on each card. Read-only without `tables.write`.
   - **Graph** — `RelationGraph` (new organism, SVG): table level draws the 57 tables coloured by group with the 83 foreign keys (the open table ringed, "neighbours only" toggle); row level draws one record with the rows it points at and the tables pointing at it. Zoom with the buttons or `+` `−` `0`, pan by drag or arrow keys, nodes are focusable, legend by group.
   - **Calendar** (`tables/TimeViews.tsx` → `CalendarView` organism, 0046) — three modes: **month** (Monday first, a ring on today, up to three chips a day, "+N more" opens that day's agenda), **week** (an all-day row and hour rows) and **agenda** (a list by day; the phone default). Chips take the tone of the row's status. Keyboard: arrows move the day, PageUp / PageDown the month, `t` goes to today, Enter opens the row. Clicking an empty day creates a row with the date prefilled (`tables.write` only). Weekday and month names come from `Intl`.
   - **Timeline** (`TimelineView` organism, 0046) — bars from the date column to the end column (a diamond when there is no end), lanes by the view's group-by, zoom day / week / month / quarter with the buttons or `+` `−`, a today line, scroll-snap and arrow-key scrolling; labels sit beside short bars. Bars open the row.
6. **`RowDrawer`** (`tables/RowDrawer.tsx`) — fields by type; foreign-key pickers by title (with search above 50 rows); ES / EN inputs for bilingual `json` columns; a *System fields* group (`id`, `tenant_id`, timestamps); a *Related* section with one list per reverse relation, each with a count and a link; "Show in the graph"; delete with an in-product confirm.

## URL params (a linkable view)
| Param | Meaning |
| --- | --- |
| `?id=<row id>` | opens that row's drawer (foreign-key chips use it) |
| `?view=<kind>` | grid, list, gallery, kanban, calendar, timeline, graph |
| `?date=<YYYY-MM-DD>` | the calendar / timeline cursor; without it, today when the period has rows, else the nearest row |
| `?mode=<month\|week\|agenda>` | the calendar layout |
| `?zoom=<day\|week\|month\|quarter>` | the timeline zoom |
| `?v=<view id>` | applies a saved view (`table_views`) |
| `?focus=<row id>` | centres the row-level graph on that row |
| `?where=<column>:<value>` | opens the table filtered (the drawer's Related links use it) |

Examples: `/#/admin/tables/bookings?view=graph`, `/#/admin/tables/class_sessions?view=calendar&mode=month&date=2026-09-29`.

## Logic and integrations
- One pipeline for every view: rows → filters (AND) → search (display text of the visible columns) → sorts → view. Calendar and timeline place a row by `config.dateColumn` (default `dateColumnOf`) and end it at `config.endColumn` (default `endColumnOf`, the pair such as `starts_at` → `ends_at`, or a point); a date key or a timestamp both work. Filters, sorts, group by, hidden columns, column order, card fields and the board column are the view state; "Save view" stores exactly that in `table_views.config`.
- Labels: `columnLabel()` = `ColumnDef.label` → the ES / EN dictionary in `src/data/labels.ts` (~300 terms) → `humanizeName()`; `tableLabel()` = `TableDef.label`; `rowTitle()` = `titleColumn` → first text column → id.
- Relations come from `ColumnDef.references` (`src/data/relations.ts`: `getRelations` 83 edges, `neighborsOf`, `reverseName`, `schemaGraph`, `layoutGraph` — a seeded force layout, identical on every render). `tenant_id` is left out.
- Technical names (`snake_case`) show only in dev mode, behind the `technical` preference (default on in dev mode). Exports use the raw column names and raw values.
- Per-viewer conveniences (sidebar state, open groups, pinned, recent, technical toggle) live in `localStorage['hoyos.tables.prefs']`; view state that is shared lives in `table_views` (D-0021).
- Integrations: `DataProvider` (MockProvider today, SupabaseProvider later): list / peek / insert / update / remove / subscribe. Nothing else.

## States
- No table picked (overview of every group)
- Grid · List · Gallery · Board · Calendar (month · week · agenda) · Timeline (four zooms) · Graph (table level) · Graph (row level)
- Calendar / timeline on a period with no rows (the cursor jumps to the nearest row), create-on-day for `tables.write`, read-only otherwise
- Filtered to no rows
- Sidebar expanded / rail / phone sheet; search with no matching table
- Row drawer (edit); read-only for finance and developer
- Delete confirm and reset-demo-data confirm (in-product dialogs)
- Board without an option column
- Calendar / Timeline disabled with a hint on tables without a date or timestamp column (e.g. `tenants`)
- Rename and delete a saved view (in-product dialogs; hidden without permission)
- Technical names on (dev mode)

## Real vs mock
- Real: labels, sidebar, every view (grid, list, gallery, board, calendar, timeline, graph), the date picker, filters, sorts, grouping, hidden columns, saved views as `table_views` rows through the `DataProvider`, the relations and graph derived from the schema, the row drawer with related rows, the URL params the rename / delete of saved views and the 17 declared actions.
- Mock / pending: data is the browser-local `MockProvider` seed (`SEED_VERSION` 8); enum badges use one Spanish gender form until per-column labels land (B1); date and slug `titleColumn`s show as chip and bar titles until B1 labels; the timeline opens rows only (no drag-to-reschedule); `time` columns cannot drive a calendar; the toolbar wraps to three rows at 1280 with the date picker; the table-level graph overlaps labels around `users` (44 incoming keys). No presence, offline queue or optimistic `version` yet (Pass C in `docs/plans/tables-system.md`).

**Resumen (ES).** Tablas y relaciones. El gestor de datos del estudio con vistas: cualquiera de las 57 tablas se abre como cuadrícula, lista, galería, tablero, calendario, línea de tiempo o grafo de relaciones, con filtros, orden, agrupación, columnas y vistas guardadas para el equipo (que se pueden renombrar y eliminar). Todo en palabras (los nombres técnicos solo en modo dev), cada referencia abre la fila a la que apunta y el panel de la fila muestra quién la usa. El calendario (mes, semana, agenda) y la línea de tiempo (día, semana, mes, trimestre) colocan las filas por la columna de fecha que elijas en «Fecha / Hasta»; se navegan con el teclado y se enlazan con `?date=`, `?mode=` y `?zoom=`.
